# Recent Join Message Change — Phase 1 Implementation/Test Spec

## Scope

Make the smallest possible behavior change for `UserServiceImpl.isSeenRecently(User)`.
Do not change the listener, SQL, payload normalization, schema, or any unrelated dirty
worktree files. Production and test source are intentionally not modified in Phase 1;
this document is the implementation design for the next phase.

## Exact implementation change

File: `src/main/java/org/saturn/app/service/impl/UserServiceImpl.java`

At the existing return literal in `isSeenRecently` (currently lines 76–78), change only:

```diff
- "\\n @%s, has been seen as: _%s_ in the last 15 minutes. \\n"
+ "\\n @%s, has been seen as: _%s_ recently. \\n"
```

The resulting Java source must retain both escaped `\\n` sequences, the leading space
before `@`, the alias underscores, period, and trailing space. There is no listener change:
`UserJoinedListenerImpl` already calls `engine.userService.isSeenRecently(user)` and queues
the optional result. `OutService` already converts literal `\\n` separators at the outbound
payload boundary.

## Focused H2/service test

Add a new test file:

`src/test/java/org/saturn/app/service/impl/UserServiceImplTest.java`

Use a real `UserServiceImpl`, a real H2 connection, and a `LinkedBlockingQueue<String>`;
do not mock the service or SQL query.

1. Open an isolated in-memory database, for example:
   `jdbc:h2:mem:user_service_message;DB_CLOSE_DELAY=-1`.
2. Create only the `messages` table needed by `SqlUtil.SELECT_SEEN_RECENTLY_AS`, matching
   the H2 schema:

   ```sql
   CREATE TABLE messages (
     id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
     trip VARCHAR,
     name VARCHAR NOT NULL,
     hash VARCHAR,
     message VARCHAR,
     created_on BIGINT NOT NULL,
     channel VARCHAR,
     visibility VARCHAR CHECK (visibility IN ('PUBLIC', 'WHISPER'))
   )
   ```

3. Insert two recent audit rows with `created_on = System.currentTimeMillis()` and the same
   hash as the subject user:
   - `name = 'Alice'`, `message = 'JOINED'`;
   - `name = 'NEW-USER'`, `message = 'LEFT'`.

   Bind all values with a prepared statement. The case-variant second row exercises the
   existing case-insensitive joining-nick filter. Both rows are inside the query's 900000 ms
   window and satisfy its `JOINED`/`LEFT` predicate.
4. Construct the subject user with nick `new-user` and the same hash (for example, trip
   `trip-a`; the full `User` constructor is available), then invoke
   `new UserServiceImpl(connection, new LinkedBlockingQueue<>()).isSeenRecently(user)`.
5. Assert the result is present and assert the exact runtime value is:

   ```java
   "\\n @new-user, has been seen as: _Alice_ recently. \\n"
   ```

   This one exact assertion covers the new wording, escaped separators, punctuation, and
   the retained alias formatting.
6. Add explicit focused assertions to make failures diagnostic:
   - `contains("recently")`;
   - `doesNotContain("in the last 15 minutes")`;
   - `doesNotContain("NEW-USER")` and `doesNotContain("new-user_")` (the joining nick is
     filtered case-insensitively from the alias list);
   - `contains("\\n")` and `doesNotContain("\n")`, proving the service still returns
     literal escaped separators rather than real line feeds.

Optionally add a small second test with only one recent row whose name equals the joining
nick ignoring case and assert `Optional.empty()`. This preserves the existing no-notification
behavior, but it is not required to validate the requested literal-only change.
