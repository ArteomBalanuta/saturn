# Saturn GAP Targets 1, 2, and 4 — Narrow Completion Specification

**Status:** architecture specification; Java source and tests intentionally not modified by this task.

## 1. Scope and evidence

This specification is grounded in the current checkout and the two supplied analysis documents. The forensic conclusions are confirmed by source inspection:

- `DefaultAgentRouter.routeInSession` constructs `new AgentToolExecutor(registry, config, allowedTools)` and calls the public two-argument `executeAll`; that constructor supplies empty middleware/observer lists and the public batch path supplies `AgentToolBatchContext.unlimited()`.
- `AgentToolExecutor.execute` currently constructs `AgentToolExecutionContext` with `Instant.MAX` and `approvalPresent=false`; it does not receive the batch context.
- `AgentToolCallScheduler.executeParallel` labels submission-time cancellation as `TOOL_BATCH_DEADLINE`, and `AgentScheduledToolCall.deadline` is populated but never read.
- `AgentToolExecutionPolicy` contains classification/conflict logic that the scheduler duplicates rather than consuming.
- `AgentToolDescriptor` rejects read/write key overlap without a documented product invariant.
- `AgentPreparedRequest` carries projection accounting, but `DefaultAgentRouter` discards it before each `LlmRequest`; the provider boundary has no projection contract or assertion.
- Existing focused evidence is the reported 163 passing, 0 failing, 5 skipped suite; formatting and diff checks pass. The full-suite `AgentConfig` max-token mismatch (actual 1024 versus expected 768) is unrelated and remains separate.

Authoritative constraints are: preserve Saturn's typed results, strict argument validation, registry/catalog, gateway authorization, ledger, session locks, and synchronous router; do not add RPC, MCP, SKILL, dynamic registry, generic parser repair, or a wholesale async rewrite.

## 3. Target 1 — exactly-once execution seam

### Production construction and injection

Retain the seam; do not remove it. Make `AgentToolExecutionMiddleware` and `AgentToolExecutionObserver` public interfaces (additive API; existing package callers continue to compile). Add a public immutable `AgentToolExecutionHooks` value (or equivalent constructor parameters) in the execution package containing defensive copies of middleware and observers. Keep existing public `AgentToolExecutor(AgentToolRegistry, AgentConfig)` and three-argument constructors unchanged and behaviorally equivalent by delegating to empty hooks.

Add a public `DefaultAgentRouter` constructor overload accepting hooks (after the existing six arguments), while retaining both existing constructors. `AgentRouterFactory.create` must be the production composition point: construct the configured hooks once and pass them to the router. Default production hooks may be empty for policy middleware, but the path must be real and observable (at minimum a request/tool outcome observer that records structured logs/metrics). If no approved approval provider exists, do not invent one: the default policy must fail closed only when an approval-required middleware is actually configured, and ordinary built-in tools continue through the existing `SaturnCommandGateway`/tool authorization path without duplicated checks.

The executor must construct one immutable context per validated call and invoke the chain exactly once around the existing timeout-backed continuation. Preserve registry lookup, validator behavior, ledger reservation/accounting, timeout, result-schema validation, error codes, and request-local executor ownership. Observers receive outcomes and cannot invoke handlers, mutate results, or prevent later observers. Observer exceptions remain isolated. A middleware may short-circuit only with an explicitly classified non-executed/blocked result; it must not fabricate a success that is indistinguishable from a handler success. If retaining short-circuit success is required, add provenance internally and ensure only a continuation-produced success is ledger-success-accounted.

Clarify scope: validation, unavailable-tool, duplicate, limit, and prerequisite outcomes either remain outside the execution middleware or are sent through a separate `onRejected` observer hook. Choose the smaller compatible option: keep middleware around validated/reserved invocation only, document it, and add observer coverage for all post-reservation terminal outcomes.

## 4. Target 4 — batch context and result semantics

`AgentToolBatchContext` is the sole source of batch deadline/cancellation state. Add factories/accessors sufficient for production and tests, including a distinct cancellation reason/state (`NONE`, `EXPLICIT`, `DEADLINE`) or equivalent monotonic state. `expired()` must be deadline-only; explicit cancellation must never imply expiry.

Add a request-level batch deadline without changing old public constructors or `AgentConfig`. The concrete first implementation is: at the start of each routed invocation, compute `routeDeadline = Instant.now().plus(config.timeout())`; for every tool-call response create a batch context with that same route deadline and a fresh cancellation token. This reuses Saturn's existing bounded request/provider timeout rather than inventing a new configuration key; a later dedicated batch setting is explicitly out of scope. A future additive `AgentExecutionLimits` batch-timeout accessor may replace this derivation only when configuration ownership is approved. The router passes this context to `AgentToolExecutor.executeAll(context, calls, batch)`. Preserve the public two-argument `executeAll` as an unlimited compatibility path for existing callers and unit tests.

`AgentToolExecutor.executeAll` passes the same batch context into every scheduled call. `execute(...)` must create `AgentToolExecutionContext` with the batch deadline, cancellation token (add this field), and approval state supplied by hooks/context—not `Instant.MAX`/hard-coded false. `AgentToolInvoker` interruption remains honored; the batch token is checked before invocation and at scheduler wait/submission boundaries.

Use distinct result codes:

- `TOOL_BATCH_CANCELLED`: explicit token cancellation, including siblings not started and futures cancelled because a caller cancelled.
- `TOOL_BATCH_DEADLINE`: deadline expiry or `Future.get` timeout attributable to the batch deadline.
- `TOOL_INTERRUPTED`: executor-thread interruption unrelated to explicit batch cancellation/deadline; always restore the interrupt flag.
- Existing `TOOL_TIMEOUT` remains the per-tool descriptor timeout; `TOOL_EXECUTION_FAILED` remains ordinary failure.

When a deadline expires, cancel outstanding futures and mark all not-completed calls with `TOOL_BATCH_DEADLINE`. When explicit cancellation occurs, cancel outstanding futures and mark all not-completed calls `TOOL_BATCH_CANCELLED`. Already completed results remain unchanged. A sibling interrupted during cancellation must be classified by the batch cancellation reason, not by wall-clock observation. Preserve input/provider order and exactly one result per call.

Remove `AgentScheduledToolCall.deadline` because the batch owns the deadline and the field is dead state. Retain its existing two-argument compatibility constructor and resource/mode fields. If removal would break package tests, deprecate the accessor for one release and stop populating/consulting it; do not maintain two deadline authorities.

## 5. Scheduler/policy unification

Make `AgentToolExecutionPolicy` the only classifier. Add a package-private immutable classification/segment decision that includes mode and resource compatibility. `AgentToolExecutor.classify` calls policy once per descriptor and passes the resulting decision to `AgentScheduledToolCall`; `AgentToolCallScheduler.parallelBatchEnd` asks the policy for compatibility and never reimplements set intersection. Remove or delegate scheduler-local `compatible` logic.

Rules remain conservative and contiguous: only read-only, idempotent, prerequisite-free calls may be in a parallel segment; unknown-resource calls, interactive/action calls, prerequisite-bearing calls, and any conflict are barriers; provider order is retained. No general DAG is introduced. Test policy decisions directly and scheduler segmentation through the same policy instance/contract.

### Resource overlap decision

Relax the descriptor constructor’s rejection of a key appearing in both read and write sets. Overlap is a legitimate read-modify-write declaration and must be treated as a write hazard: a call with any write key conflicts with another call reading or writing that key, and a call declaring both read and write is never parallelized with a call touching that key. Empty sets retain “unknown resource” conservative semantics when paired with known resources. This is safer and more expressive than rejecting a valid contract, while preserving no-overlap parallel reads. Add constructor immutability/nonblank tests and read/write, write/write, read-modify-write conflict tests.

## 6. Target 2 — provider projection contract and observability

Keep durable history untouched and continue using copy-only `AgentMessageProjector`. Harden `project` for empty input/system invariants and deep-copy any mutable `LlmMessage` internals that are not already immutable. Preserve system prompt, current live user tail, complete assistant tool-call/result units, lineage/order, and `ToolResultMode`; drop malformed/orphan units only under an explicit sanitization policy with metadata.

Carry `AgentContextProjection` from `AgentPreparedRequest` into every provider request, including the initial request, post-tool replacement request, correction/finalization request, and any fresh-data request. Add an additive provider-neutral projection metadata field to `LlmRequest` with compatibility constructors preserving existing call sites. Metadata must include serialized character count, estimated-token method/version, budget, pruned/overflow flags, removed units, and fingerprint of the exact `LlmRequest.messages()` list. Recompute/assert the fingerprint at construction or provider boundary so stale metadata cannot silently describe a different payload.

`OpenAiCompatibleClient.complete` must consume the metadata for structured debug/metrics logging (request ID may be carried separately if available) and not send Saturn-only metadata to the remote API unless explicitly namespaced and contract-approved. Provider contract tests must capture the exact HTTP payload and assert: payload messages hash to metadata fingerprint, no durable input mutation occurred, projection flags/counts match the sent list, and old two-argument `LlmRequest` behavior remains metadata-empty and wire-compatible.

Do not claim tokenizer-accurate accounting: retain the documented UTF-8 serialized-character accounting and versioned `(chars + 3) / 4` estimate until a provider tokenizer is introduced. Do not add compression in this completion.
